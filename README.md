# kojintodo（Kojin ToDo）

個人用のタスク管理・ToDo管理アプリです。
毎日のルーティン（Daily）、通常のToDo、重要度×緊急度の4象限マトリクスを1つの画面で管理し、**重要な仕事に集中する**ことを目的としています。
あわせて、ビジョンボード（Vision）と日記で「なりたい姿 → 毎日の行動 → 振り返り」をつなげ、**1% better everyday** を積み上げられるようにしています。

HTML / CSS / JavaScript だけで動く静的なWebアプリで、ビルドやインストールは不要です。データはブラウザの localStorage に保存されます。
Firebase を設定してログインすると、**PC とスマートフォンの間でデータを自動同期**できます（任意）。

---

## 主な機能

| 機能 | 内容 |
| --- | --- |
| Dailyタスク | 毎日（または指定した曜日）に繰り返すタスク。完了チェックは日付が変わると自動でリセット。直近7日間の記録と連続達成数を表示 |
| ToDoリスト | 締切日ごと（期限切れ／今日／明日／7日以内／それ以降／期限なし）に自動で整理。未完了・完了を切り替えて表示 |
| 4象限マトリクス | 重要度×緊急度で「今すぐやる／計画してやる／任せる・手早く／やらない・後回し」に分類。PCはドラッグ＆ドロップで移動 |
| 今日（ホーム） | 今日のDaily・期限切れと今日締切のToDo・重要なタスクをまとめて表示し、進捗率を円グラフで表示 |
| 追加・編集・削除 | クイック追加（Enterで即追加）と、締切日・象限・メモまで設定できる詳細ダイアログ。削除は「元に戻す」が可能 |
| 完了管理 | チェックで完了／未完了を切り替え。完了済みタスクの一括削除（元に戻す可） |
| 締切日 | 「今日／明日／1週間後／なし」のワンタップ設定。期限切れは赤、今日締切はオレンジで強調 |
| データ保存 | localStorage へ自動保存。JSON でのエクスポート／インポート（バックアップ・端末間の移行用） |
| PC・スマホ同期（任意） | Google アカウントまたはメールアドレスでログインすると、追加・編集・完了・削除が数秒で他の端末に反映。オフライン中の変更は接続が戻ったときに自動送信 |
| PC・スマホ対応 | PCはサイドバー、スマホは下部タブバー＋下から出るシート型のダイアログ。ダークモードにも対応 |
| Vision | ビジョンボード画像（タップで全画面）、日替わりの「今日の言葉」、キーワード、なりたい姿を表示 |
| 1%の複利メーター | 「前進した日」（Daily をすべて完了した日、または日記に「今日の1%成長」を書いた日）を数え、1.01 の n 乗で今の倍率を表示 |
| ビジョンの年へのカウントダウン | 例：「2027年まであと36日」、2027年に入ると「2027年の進捗 ○%」 |
| 日記 | 1日1ページ。気分（5段階）・今日の1%成長・良かったこと3つ・明日の自分へ一言・自由メモ。入力すると自動保存。その日の Daily 達成数と完了 ToDo 数を自動表示。カレンダーで見返せる（気分の色つき）・連続記録 |
| 完了の演出 | チェック時に輪が広がるアニメーションと振動（Android）。その日の Daily をすべて完了するとお祝い画面 |
| アプリとしてインストール | Android（Pixel など）の Chrome から「アプリをインストール」で、アドレスバーのない全画面アプリとして起動 |
| 最初に開く画面 | アプリを開いたときの画面を「今日／Vision／日記」から選択（端末ごと） |

## 画面構成

```
┌───────────────┬──────────────────────────────────────┐
│ サイドバー      │  メイン画面                              │
│ タスク          │                                        │
│  ・今日         │   今日     … 今日やることのダッシュボード      │
│  ・Daily        │   Daily    … 繰り返しタスクの管理            │
│  ・ToDo         │   ToDo     … 締切日別のタスク一覧            │
│  ・マトリクス    │   マトリクス … 重要度×緊急度の4象限           │
│ ライフ          │                                        │
│  ・Vision       │   Vision   … ビジョンボード・1%メーター        │
│  ・日記         │   日記     … 1日3分の振り返り・カレンダー      │
│  ・設定・データ  │                                        │
└───────────────┴──────────────────────────────────────┘
※ スマートフォンでは、画面上部の「タスク／ライフ」で切り替え、下部のタブバーで画面を選びます
```

画面はURLのハッシュ（`#today` `#daily` `#todo` `#matrix` `#vision` `#journal`）で切り替わるため、ブラウザの戻る操作やブックマークにも対応しています。

## 起動方法

### 1. ファイルを直接開く（いちばん簡単）

1. このリポジトリをダウンロード（またはクローン）します。
   ```bash
   git clone https://github.com/atot7422kah5-ui/kojintodo.git
   ```
2. フォルダ内の `index.html` をダブルクリックし、ブラウザ（Chrome / Edge / Safari / Firefox）で開きます。

サーバーやインストールは不要です。

### 2. ローカルサーバーで開く（任意）

Python が入っている環境では、次のコマンドでも起動できます。

```bash
cd kojintodo
```

```bash
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。

### 3. スマートフォンで使う

- **同じWi-Fi内で試す**：PCで次のコマンドを実行し、スマホのブラウザで `http://<PCのIPアドレス>:8000` を開きます。
  ```bash
  python3 -m http.server 8000 --bind 0.0.0.0
  ```
- **常用する**：GitHub Pages などの静的サイトホスティングで公開すると、スマホからいつでもアクセスできます（GitHub Pages はリポジトリの公開設定やプランによって利用条件が異なります）。公開後、Safari の共有メニュー「ホーム画面に追加」でアプリのように起動できます。

> **データの保存先について**
> ログインしていない間、データは「端末 × ブラウザ × URL」ごとに別々に保存されます。PC とスマホで同じデータを使うには、下記の「同期機能の設定」を行ってログインしてください。

## 同期機能の設定（Firebase）

PC とスマホで同じデータを使うための設定です。Google の Firebase（無料プラン）を使います。所要時間は15分ほどです。
設定しない場合も、これまでどおり各端末だけで使えます。

### 1. Firebase プロジェクトを作る
1. https://console.firebase.google.com を開き、Google アカウントでログインします。
2. 「プロジェクトを作成」を押し、名前（例：`kojintodo`）を入力します。Google アナリティクスはオフで構いません。

### 2. ログイン方法を有効にする
1. 左メニューの「構築」→「Authentication」→「始める」を押します。
2. 「Sign-in method（ログイン方法）」タブで次の2つを有効にして保存します。
   - **Google**（プロジェクトのサポートメールを選択）
   - **メール / パスワード**
3. 「設定」タブ →「承認済みドメイン」→「ドメインを追加」で、公開先のドメインを追加します。
   - GitHub Pages の場合：`atot7422kah5-ui.github.io`

### 3. データベースを作る
1. 左メニューの「構築」→「Firestore Database」→「データベースを作成」を押します。
2. ロケーションは `asia-northeast1（東京）` を選び、「本番環境モード」で作成します。
3. 作成後、「ルール」タブを開き、このリポジトリの [`firestore.rules`](firestore.rules) の内容に置き換えて「公開」を押します。
   （ログインした本人だけが自分のデータを読み書きできる設定です）

### 4. 設定値をアプリに書き込む
1. 「プロジェクトの概要」の横の歯車 →「プロジェクトの設定」→「マイアプリ」で、ウェブ（`</>`）アイコンを押します。
2. ニックネーム（例：`kojintodo`）を入力して「アプリを登録」を押します（Firebase Hosting の設定は不要です）。
3. 表示された `firebaseConfig` の値を、[`js/firebase-config.js`](js/firebase-config.js) の `window.KOJIN_FIREBASE_CONFIG = null;` の部分に貼り付けます。
4. 変更を GitHub の main に反映すると、公開中のページで同期が使えるようになります。

> `firebaseConfig` の値は Web アプリに公開される前提の識別子で、パスワードではありません。公開リポジトリに置いても、データは手順3のセキュリティルールで保護されます。

### 同期機能の使い方
- 「設定・データ」→「PC・スマホの同期」から、**すべての端末で同じ方法**（Google またはメールアドレス）でログインします。方法が違うと別のアカウントになり、データが共有されません。
- 初めてログインした端末にデータがある場合は、クラウドのデータに追加するかを確認します。
- ログイン中は、サイドバー（スマホは右上）に「同期済み」「同期中」「オフライン」などの状態が表示されます。
- ログアウトすると、その端末からはデータが消えます（クラウドには残り、再度ログインすると表示されます）。
- iPhone の「ホーム画面に追加」から起動したときに Google ログインがうまくいかない場合は、メールアドレスでのログインを使ってください（その場合は PC もメールアドレスでログインします）。
- `index.html` をファイルとして直接開いた場合は同期できません。公開したページ（`https://`）で使ってください。
- 業務の情報（候補者の氏名など）を書く場合は、個人の Google アカウントのクラウドに保存してよいか、所属組織の情報管理ルールを確認してください。

### 4. Pixel（Android）にアプリとしてインストールする

1. Chrome で公開したページ（`https://atot7422kah5-ui.github.io/kojintodo/`）を開きます。
2. 右上の「︙」メニュー →「**アプリをインストール**」（表示されない場合は「ホーム画面に追加」）を選びます。
3. ホーム画面とアプリ一覧にアイコンが追加され、アドレスバーのない全画面で起動します。ログイン状態は Chrome と共通です。

## 使い方

### タスクを追加する
- 各画面上部の入力欄にタスク名を入力して **Enter**（または「追加」）。
  - 「今日」画面から追加 → 締切が今日のToDo
  - 「ToDo」画面から追加 → 締切なしのToDo
  - 「Daily」画面から追加 → 毎日繰り返すDaily
  - 「マトリクス」の各象限の「追加」欄 → その象限に分類されたToDo
- 締切日・重要度×緊急度・メモ（Dailyは曜日）も設定したいときは「**詳細**」を押します。

### 編集・削除・完了
- タスク名をクリック（タップ）すると編集ダイアログが開きます。削除もここから行えます。
- PCではタスクにマウスを乗せると右端にゴミ箱アイコンが表示されます。
- 左の丸いチェックで完了／未完了を切り替えます。
- 削除した直後に表示される「**元に戻す**」で復元できます。

### マトリクスで優先順位を整理する
- PC：タスクをドラッグして別の象限（または「未分類」）へドロップします。
- スマホ：タスクをタップし、編集ダイアログの「重要度 × 緊急度」で象限を選びます。

### Vision を設定する
- 「Vision」画面の「画像を選ぶ」でビジョンボード画像を1枚選びます。画像はこの端末で圧縮（長辺 最大1800px・約500KB程度）してから保存します。
- 「編集」から、タイトル・ビジョンの年・キーワード（1行に1つ）・なりたい姿を設定します。キーワードは「今日の言葉」として日替わりで表示されます。
- 毎朝ボードを見たい場合は、「設定・データ」→「アプリを開いたときの画面」を「Vision」にします。

### 日記を書く
- 「日記」画面で、気分・今日の1%成長・良かったこと・明日の自分へ一言・自由メモを入力します。入力すると自動で保存されます。
- `‹` `›` やカレンダーで過去の日記を開けます（未来の日付は選べません）。すべての項目を空にすると、その日の日記は削除されます。

### キーボードショートカット（PC）
| キー | 動作 |
| --- | --- |
| `N` | 追加欄にカーソルを移動 |
| `1`〜`6` | 今日／Daily／ToDo／マトリクス／Vision／日記に切り替え |
| `Esc` | ダイアログを閉じる・入力欄から抜ける |

## システム構成

### ディレクトリ構成

```
kojintodo/
├── index.html              … 画面の骨組み（ナビゲーション・ダイアログ）
├── css/
│   └── style.css           … デザイン（ライト／ダーク、PC／スマホのレイアウト）
├── js/
│   ├── utils.js            … 日付計算・HTMLエスケープなどの共通処理
│   ├── store.js            … データモデルと localStorage への保存
│   ├── views.js            … 各画面の HTML を組み立てる処理
│   ├── firebase-config.js  … 同期機能（Firebase）の設定値。未設定なら同期オフ
│   ├── sync.js             … Firebase によるログインと PC・スマホ間の同期
│   └── app.js              … 画面切り替え・操作イベント・ダイアログ・ドラッグ＆ドロップ
├── assets/
│   ├── icon.svg            … ファビコン
│   ├── icon-192.png / icon-512.png / icon-maskable-512.png … アプリのアイコン
│   └── apple-touch-icon.png … iPhone のホーム画面用アイコン
├── manifest.webmanifest    … アプリとしてインストールするための設定
├── firestore.rules         … Firestore のセキュリティルール（本人だけが読み書きできる）
└── README.md
```

### 処理の流れ

```
 操作（クリック・入力）
        │
        ▼
   app.js ──── store.js の関数を呼ぶ（addTodo / setDailyDone など）
                    │
                    ├─ ① データを更新
                    ├─ ② localStorage に保存
                    └─ ③ 変更を通知
                            │
                            ▼
   app.js が再描画 ── views.js が現在の画面の HTML を生成
```

- データの変更は必ず `store.js` を経由します。
- 同期機能（`sync.js`）は、`store.js` が通知する変更内容を Firestore に書き込み、Firestore 側の変更を受け取って `store.js` に反映します。画面側（`views.js` / `app.js`）は同期の有無を意識せずに動きます。

```
 端末A（PC）                         Firebase                          端末B（スマホ）
 store.js ─変更─▶ sync.js ──書き込み──▶ Firestore ──リアルタイム通知──▶ sync.js ─▶ store.js ─▶ 再描画
                              （users/{uid}/todos, dailies）
```

- Firestore のオフライン保存を有効にしているため、圏外での変更は接続が戻ったときに送信されます。Firebase の読み込み前に行った変更は、送信待ち（`kojintodo:v1:sync-outbox`）として端末に保管し、次回ログイン時に送信します。
- Daily の完了チェックは「完了日の追加・削除」として送るため、複数の端末で同時にチェックしても両方が残ります。
- ES Modules ではなく通常の `<script>` で読み込んでいるため、`index.html` をファイルとして直接開いても動作します。
- `index.html` が読み込む CSS・JS には `?v=日付` を付けています。ファイルを更新したときはこの値をすべて変更してください（GitHub Pages ではファイルが最大10分ブラウザに保存されるため、変更しないと新しい HTML と古い CSS・JS が混ざって表示が崩れることがあります）。

### データ仕様（localStorage）

保存キー：`kojintodo:v1`（ビジョンボード画像のみ `kojintodo:v1:vision-image` に別保存）

```json
{
  "version": 1,
  "todos": [
    {
      "id": "uuid",
      "title": "採用広報記事の構成案を作る",
      "memo": "",
      "dueDate": "2026-12-01",
      "quadrant": "q2",
      "completed": false,
      "completedAt": null,
      "createdAt": "2026-11-26T00:30:00.000Z",
      "updatedAt": "2026-11-26T00:30:00.000Z"
    }
  ],
  "dailies": [
    {
      "id": "uuid",
      "title": "応募者・エントリー状況を確認する",
      "days": [1, 2, 3, 4, 5],
      "startDate": "2026-11-26",
      "doneDates": ["2026-11-25", "2026-11-26"],
      "createdAt": "2026-11-26T00:30:00.000Z",
      "updatedAt": "2026-11-26T00:30:00.000Z"
    }
  ],
  "journals": [
    {
      "id": "2026-11-26",
      "date": "2026-11-26",
      "mood": 4,
      "growth": "朝ランを5km",
      "good": ["面談がうまくいった", "", ""],
      "tomorrow": "7時に起きる",
      "memo": "",
      "createdAt": "2026-11-26T12:00:00.000Z",
      "updatedAt": "2026-11-26T12:05:00.000Z"
    }
  ],
  "vision": {
    "id": "main",
    "title": "2027's My vision",
    "year": 2027,
    "keywords": ["1% better everyday", "Discipline"],
    "statement": "心も体も整い…",
    "updatedAt": "2026-11-26T12:00:00.000Z"
  },
  "settings": { "theme": "auto", "startView": "today" }
}
```

| 項目 | 説明 |
| --- | --- |
| `quadrant` | `q1`=重要×緊急、`q2`=重要×緊急でない、`q3`=重要でない×緊急、`q4`=重要でない×緊急でない、`null`=未分類 |
| `days` | 実施する曜日（0=日曜 〜 6=土曜） |
| `doneDates` | Dailyを完了した日付の一覧。日付ごとに記録するため、日付が変わると自動で「未完了」になります（直近約400日分を保持） |
| `settings.theme` | `auto`（OSに合わせる）/ `light` / `dark` |
| `settings.startView` | アプリを開いたときの画面（`today` / `vision` / `journal`）。端末ごとの設定 |
| `journals[].mood` | 気分（1=しんどい 〜 5=最高、未選択は `null`）。日記は日付ごとに1件 |
| ビジョンボード画像 | `{ id: "image", dataUrl, width, height, updatedAt }`。JPEG に圧縮した data URL（70万文字以下） |

- 日付は端末のローカル時刻で `YYYY-MM-DD` 形式に変換しています（日本時間の深夜〜朝9時に日付がずれないようにするため）。
- 同期中は、同じ内容を Firestore の `users/{uid}/todos/{id}`・`dailies/{id}`・`journals/{日付}`・`vision/main`・`vision/image` にも保存します（テーマと「最初に開く画面」は端末ごと）。
- 読み込み時に不正なデータは取り除き、JSON が壊れていた場合は元データを `kojintodo:v1:broken:<時刻>` に退避してから新しい状態で起動します。

## 動作環境

- Chrome / Edge / Safari / Firefox の最新版（PC・スマートフォン）
- JavaScript と localStorage が有効であること
- プライベートブラウズでは保存できない場合があります（その場合は画面上部に警告を表示します）

## 動作確認の内容

Playwright（Chromium）で以下を自動確認しています（PC 1280px／iPhone 13／iPhone SE 相当の画面幅）。

- ToDo の追加（クイック追加・詳細ダイアログ）、編集、空タイトルの入力チェック
- 完了／未完了の切り替え、削除と「元に戻す」、完了済みの一括削除
- Daily の追加・曜日指定、日付が変わったときの自動リセット、対象外の曜日、連続達成数
- マトリクスのドラッグ＆ドロップ、象限ごとの追加
- 再読み込み後のデータ保持、別タブでの変更の反映
- テーマ切り替え、エクスポート／インポート（不正ファイルの拒否を含む）、全データ削除、破損データからの復旧
- HTML を含むタスク名がスクリプトとして実行されないこと（XSS 対策）
- スマートフォン幅で横スクロールが発生しないこと、コンソールエラーがないこと

同期機能は、Firebase の動作を再現した模擬サーバーと「PC」「スマホ」2つのブラウザで確認しています。
